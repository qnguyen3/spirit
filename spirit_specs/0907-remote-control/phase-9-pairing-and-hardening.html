Phase 9 — Pairing & hardening

Multi-device pairing done properly: a QR code and LAN URLs in Settings, a paired-device list with revoke and rename, token rotation UX, pairing rate limits, session idle expiry, connection caps, audit logging, and a threat-model checklist walked through against the code.

Goal

Settings → Remote Control shows, when LAN access is on, a QR code that a phone scans to pair in one tap, the LAN URLs (IP and hostname.local), and a list "Paired devices: iPhone · Safari (last seen 2 min ago) [Revoke]". Rotating the token or revoking a device disconnects it immediately. Brute-forcing /pair is throttled. Every security invariant from D4/D5 has a test.

Prerequisites

Phases 1–8. Read specs/warp-control-cli/SECURITY.md again and the module doc of app/src/local_control/mod.rs:1-58; this phase writes the equivalent for Remote Control.

Context

  • QR encoding: the qrcode crate (0.14, default-features = false) is already a dependency of the app (app/Cargo.toml:155) and unused; QrCode::new(bytes) → to_colors()/width() gives the module matrix. WarpUI rendering: compose a Flex::column of rows of fixed-size Containers (a 4 px module → ~150 px for a version-4 code); precedent for drawing fixed boxes is the status dot in render_workspace_switcher_pill app/src/workspace/view.rs:4222-4234. An Icon::QrCode glyph exists (crates/warp_core/src/ui/icons.rs:79) for the button.
  • LAN address discovery: no interface-enumeration crate is present. Use the UDP-connect trick (std::net::UdpSocket::bind("0.0.0.0:0") → connect("10.255.255.255:1") → local_addr(); sends no packets) for the primary IPv4, and the machine hostname (hostname via the hostname crate if present in Cargo.lock, else gethostname through libc on unix / GetComputerNameExW on Windows — check what crates/warp_core already exposes before adding a dependency) for <host>.local.
  • Sessions store from Phase 1 (app/src/remote_control/sessions.rs) with the rate-limit counter struct placeholder; PairedDevice in crates/remote_control::auth.
  • Settings page slots left in Phase 1; ToastStack; DismissibleToast.
  • Logging: safe_info!/safe_warn! (crates/warp_core/src/safe_log.rs).

Tasks

Task 1 — LAN endpoints and pairing surfaces

  • app/src/remote_control/lan.rs: fn lan_endpoints(port) -> Vec<RemoteEndpoint> (primary IPv4 + hostname.local), computed at server start when LAN access is on and re-computed when the Settings page asks (a "Refresh addresses" button) — no network-change watcher in v1. Feed them into AllowedHosts.extra and ServerState::Running.lan_endpoints.
  • Settings page: when LAN access is on and the server runs — the QR code (encodes http://<ipv4>:port/pair?t=<token>), the two URLs with copy buttons, and a red warning row: "Anyone on this network who obtains this link can control your terminals. Traffic is not encrypted. Prefer Tailscale or an SSH tunnel on untrusted networks." The QR is hidden behind a "Show QR code" button (it contains the token) and hides again after 60 s or when the page loses focus.
  • Palette entry "Show Remote Control QR code" → opens Settings and expands the QR. Tray: add "Copy LAN URL" when LAN is on.

Task 2 — Paired devices

  • SessionStore gains device labels (from User-Agent at pairing; editable), revoke(device_id) (closes that device's WebSocket connections: the connection task subscribes to a per-session Notify/watch that the store triggers), revoke_all() on token rotation and on disable-with-"forget devices" (a second button in Settings: "Disconnect all devices").
  • Persistence: paired_devices setting updated on pair/revoke/rename, and last_seen flushed at most once per minute and on stop.
  • Settings widget "Paired devices": rows with label, first paired, last seen, connected dot, Revoke button (confirm), inline rename.
  • Commands devices.list, devices.revoke {device_id}, devices.rename {device_id, label} and REST equivalents; the web client settings sheet shows "This device: <label>" with rename and "Log out" (self-revoke), and the other devices with revoke.

Task 3 — Rate limits, expiry, caps

  • Pairing: per-remote-IP sliding window of failures; more than PAIR_FAILURES_PER_MINUTE → 429 for the next 60 s (constant-time regardless); every failure logged with the IP; success logged with IP + device label.
  • Sessions idle for SESSION_IDLE_DAYS are dropped at start and by an hourly sweep.
  • Connection caps already enforced (Phase 2); add per-IP cap of 4 WebSockets. Input rate limits (Phase 5) get a test.
  • Request body limit (64 KiB) and header size defaults from hyper are confirmed by tests.

Task 5 — Audit logging and diagnostics

  • Info-level lines for: server start/stop (endpoint), pairing success/failure (IP, label), WebSocket connect/disconnect (client id, IP, duration), token rotation, device revoke. Debug-level for commands (name only, never params). A "Copy diagnostics" button in Settings copies the current state (endpoints, client count, device count, limits) for bug reports — no secrets.

Out of scope

  • TLS/self-signed certificates and certificate pinning (D6, future). mDNS advertisement. Push notifications. Per-device permissions (all paired devices are equal).

Verification

  • ./script/presubmit green; every test in the threat table exists and passes.
  • Enable LAN → the QR renders; scan with an iPhone camera → Safari opens, pairs, lands on the app; the device row appears within a minute; rename it; revoke it from the desktop → the phone's socket closes and it shows the pairing page on reload; 6 wrong tokens from curl → 429.
  • Rotate the token → all devices revoked; the page reflects zero devices.
  • Disable LAN → LAN URLs and QR disappear; a phone on the LAN gets connection refused; loopback still works.
  • Tailscale check (if available): enable LAN, connect from a phone on the tailnet via the Tailscale IP after adding it to the allow-list (add an "Additional allowed hosts" text setting remote_control.extra_hosts in this phase for exactly this case).

Gotchas

  • Binding 0.0.0.0 does not tell you which IP a phone will use; the allow-list must include every address you display, and extra_hosts exists for VPN addresses. A Host mismatch shows up as 421 with no body — make the Settings warning mention "if a device sees a blank page, add its address here".
  • The UDP-connect trick returns the default-route interface; on a machine with Wi-Fi and Ethernet the "other" address is missing. The extra-hosts setting covers it; a full interface enumeration is future work.
  • Revocation must close live sockets, not just fail the next request; wire the per-session notifier into the WebSocket select loop.
  • Do not log User-Agent raw at info level (fingerprinting noise); log the parsed label.
  • QR content includes the token; never render it into a screenshot-able view by default, and never store the PNG.
