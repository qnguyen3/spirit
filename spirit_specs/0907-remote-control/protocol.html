Remote Control — Wire Protocol Reference

The HTTP surface, authentication, WebSocket message catalog, binary terminal frames, error codes and limits. Types live in crates/remote_control/src/protocol.rs; this page is the human-readable contract that the Rust types and the JavaScript client both follow. Phases 2–9 add messages incrementally; the tables mark the phase that introduces each item.

Conventions

  • PROTOCOL_VERSION = 1 (crates/remote_control/src/lib.rs). Additive changes (new optional fields, new commands, new events) keep the version; renames/removals bump it. The client refuses a hello whose protocol differs and shows "Update Spirit / reload".
  • All JSON uses snake_case keys. Enums serialize as snake_case strings. Message envelopes use #[serde(tag = "type", rename_all = "snake_case")]; commands use {"type":"command","id":…,"name":…,"params":{…}} with name from the CommandName enum (#[serde(rename_all = "snake_case")], values like "tab.activate" via explicit #[serde(rename)]).
  • Ids are strings (D10). Timestamps are Unix milliseconds (i64). Byte payloads inside JSON are base64 (standard alphabet, padded). Unknown fields are ignored by both sides (serde default); unknown message types are logged and ignored by the client, rejected with invalid_request by the server.
  • Every server → client JSON message is one of ServerMessage; every client → server JSON message is one of ClientMessage. Both enums are exhaustively matched.

Auth extractor semantics (Phase 1): cookie spirit_rc → session lookup (in-memory map keyed by the SHA-256 of the session id) → touch last_seen. Or Authorization: Bearer <access token> (constant-time). Otherwise 401 {"error":{"code":"unauthorized"}} for /api/*, or the pairing page for /. Mutating REST routes (POST/DELETE) also require Origin to match and X-Spirit-Remote: 1; failures are 403 {"error":{"code":"forbidden_origin"}}.

Host check (Phase 1, before routing): the Host header (with or without port) must be one of: 127.0.0.1:<port>, localhost:<port>, [::1]:<port>, and, when LAN access is on, every address in lan_endpoints plus <hostname>.local:<port>. Otherwise 421 Misdirected Request with an empty body. Implemented in crates/remote_control::hosts::AllowedHosts with unit tests for IPv6 brackets, missing port, uppercase, trailing dot.

WebSocket lifecycle

  1. Client connects to ws://<host>/api/v1/ws. Server sends hello, then immediately a full state.
  2. Client sends ping every 15 s; server answers pong. Server closes idle sockets after 60 s without any frame. Server sends WebSocket-level pings too (axum/tungstenite handles pongs).
  3. State changes arrive as state messages (full snapshot, increasing version). The client replaces its store wholesale and re-renders (cheap at this size).
  4. Commands are request/response: the client picks a unique id; the server always answers with exactly one result for that id, possibly seconds later for deferred operations (worktree creation, clone). The client times out at 30 s (120 s for project.clone) and shows an error, but a late result is still honored if the id is known.
  5. Terminal streams: terminal.attach returns an attach_id; from then on binary frames tagged with that id carry PTY bytes until terminal.detach or the socket closes. A server-initiated terminal.resync event means "reset xterm and apply this snapshot" (after overflow, resize or mode swap).
  6. Disconnect: the client reconnects with exponential backoff (0.5 s → 8 s, jitter). On a new hello with a different instance_id, the client drops all cached state and re-attaches nothing (ids are dead). With the same instance_id it re-attaches the terminal it was viewing.

Binary frames (terminal bytes) — Phase 4/5

server → client:  [attach_id: u32 little-endian][pty bytes…]        raw output as read from the PTY, coalesced (≤16 KiB or 8 ms)
client → server:  [attach_id: u32 little-endian][input bytes…]      raw bytes to write to the PTY (Phase 5), max 4 KiB per frame

Binary input frames are the hot path for keystrokes; the JSON terminal.input command exists for tests and for clients without binary support, and both feed TerminalView::write_viewer_bytes_to_pty. Text frames never carry terminal bytes.

Size budget: a snapshot with 3 windows × 5 screens × 10 tabs × 2 panes is ~40 KB pretty-printed; fine for full pushes. Derive Clone, Debug, PartialEq, Serialize, Deserialize on all of them; PartialEq is what the bridge diffs on.
