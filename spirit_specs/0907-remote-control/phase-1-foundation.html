Phase 1 — Foundation

Feature flag, settings and secure token, the RemoteControlServer lifecycle on a private tokio runtime, pairing with cookie sessions, Host/Origin hardening, embedded static assets, and every desktop surface: Settings page, Command Palette entries, tray entry, top-bar pill. At the end a browser can pair and load a placeholder page.

Goal

Settings → Remote Control → Enable starts a loopback HTTP server; the page shows the URL, a copy button, an Open-in-browser button and a masked access token; opening the pairing URL sets a session cookie and shows a placeholder page reading "Spirit Remote Control — paired"; disabling the setting stops the server and invalidates nothing on disk except the in-memory connections; the flag off makes all of this vanish.

Prerequisites

None. Read index.html fully (especially D1–D6, D11, D18, D19 and the global rules), and skim app/src/local_control/mod.rs and app/src/settings/local_control.rs end to end.

Gotchas

  • Do not put the token in settings.toml. The public settings file is user-editable and often committed to dotfiles; only the SecureSetting path is acceptable (D4).
  • Bind synchronously. local_control uses runtime.block_on(TcpListener::bind); binding with std::net first gives the same immediacy without entering the runtime on the main thread for longer than from_std needs. Never block_on anything that could wait.
  • Dropping the runtime from the main thread blocks until worker threads finish their current poll; keep handlers short and never do blocking file IO inside them (the sessions persistence hop goes through the spawner, not direct settings writes from tokio).
  • The settings subscription fires for every field. Compare the previous (enabled, port, lan) tuple and only restart when something relevant changed, or the page's Reveal button would restart the server.
  • Origin is absent on same-origin GET navigations and present on WebSocket upgrades and cross-site POSTs. That is why GET routes only check Host while mutating routes and the upgrade check Origin. Do not require Origin on GET.
  • SameSite=Strict means the pairing redirect must be same-site: when the user opens the pairing link from an external app, the first navigation carries no cookie yet — that is fine because /pair sets it and 303s to /, a same-site navigation.
  • The tray on macOS rebuilds the whole menu via ctx.set_status_item; keep the entry diff-friendly (stable label) so refresh's early-return keeps working.
  • Feature-gated settings groups must not be read when the flag is off (they are unregistered, and as_ref would panic). Every reader checks the flag first — including the pill and the tray.
  • Windows: binding 0.0.0.0 may trigger a firewall prompt; loopback does not. Nothing else is platform-specific in this phase; keep #[cfg(unix)] out of this module entirely.
