Phase 4 — Terminal live view

Read-only mirroring of any terminal: a grid→ANSI serializer, an attach snapshot (recent history + live screen + DECSET modes), the PTY byte relay over binary WebSocket frames with overflow/resync handling, and the xterm.js viewer sized to the desktop. The hardest phase; read every gotcha.

Goal

Opening a terminal in the web UI shows what the desktop pane shows — recent output as scrollback, the live screen (a running top, a Claude Code TUI, vim in the alt screen) pixel-for-character faithful — and keeps updating as bytes arrive, with the same cols×rows as the desktop, scaled to fit a phone. Desktop resizes and mode swaps re-sync the view. Nothing is typed yet.

Prerequisites

Phases 1–3. Read the terminal-model part of index.html and D8/D9. Re-read the locking rules.

Tasks

Task 1 — Grid → ANSI serializer (crates/warp_terminal/src/model/ansi_export.rs)

  • pub struct ScreenExport { pub rows: usize, pub cols: usize } and pub fn grid_screen_to_ansi(grid: &GridHandler, rows: usize, cols: usize, cursor: Point, cursor_visible: bool, out: &mut Vec<u8>): emits, for each of the last rows rows of the grid (padding with blank rows when the grid is shorter), CSI {r};1 H, then the cells with minimal SGR transitions (track current fg/bg/flags; emit SGR 0 then the full attribute set whenever anything changes — correctness over minimality), Color::Named → 30–37/90–97 (and 40–47/100–107), Color::Indexed → 38;5;n/48;5;n, Color::Spec → 38;2;r;g;b/48;2; flags BOLD, DIM, ITALIC, UNDERLINE (and DOUBLE_UNDERLINE → 4:2), INVERSE, HIDDEN, STRIKEOUT; WIDE_CHAR_SPACER/LEADING_WIDE_CHAR_SPACER cells are skipped (the wide char already advanced two columns); content_for_display() for text (this maps the null default char to a space); trailing blank cells are trimmed with CSI K. After the rows: CSI {cursor.row+1};{cursor.col+1} H then CSI ?25h or ?25l. Never emit line feeds inside the screen dump — absolute positioning avoids wrap/scroll ambiguity.
  • pub fn rows_to_ansi_text(grid: &GridHandler, range: Range<usize>, out: &mut Vec<u8>): history-style export — rows joined with \r\n except where row_wraps(i) is true (wrapped rows are joined without a newline so xterm re-wraps them at its width, which equals ours), same SGR logic, SGR 0 at the end. Used for completed blocks' output and for the part of the active grid above the visible window.
  • pub fn modes_to_ansi(modes: &dyn ModeProvider, out: &mut Vec<u8>): for each of APP_CURSOR (?1), APP_KEYPAD (=/> keypad), BRACKETED_PASTE (?2004), MOUSE_REPORT_CLICK (?1000), MOUSE_DRAG (?1002), MOUSE_MOTION (?1003), SGR_MOUSE (?1006), UTF8_MOUSE (?1005), FOCUS_IN_OUT (?1004), ALTERNATE_SCROLL (?1007), LINE_WRAP (?7), ORIGIN (?6), INSERT (4), LINE_FEED_NEW_LINE (20): emit set or reset explicitly so xterm's state matches regardless of its defaults. Kitty keyboard flags are not emitted (xterm.js does not implement the protocol; Phase 5 encodes keys accordingly).
  • Tests ansi_export_tests.rs: feed a byte script into a fresh grid via the existing processor helpers, export, feed the export into a second fresh grid of the same size, and assert cell-by-cell equality of chars, fg, bg and the attribute flags on the visible screen, plus cursor equality — scripts: plain text, 16/256/truecolor colors, bold+underline+inverse mixes, wide CJK characters, a screen exactly rows tall, a screen shorter than rows, a cursor at the last column, a hidden cursor. A separate test asserts modes_to_ansi round-trips every listed mode.

Task 2 — Attach snapshot (app/src/remote_control/terminal_snapshot.rs)

  • pub(crate) struct AttachSnapshot { bytes: Vec<u8>, cols: usize, rows: usize, mode: TerminalMode } and pub(crate) fn build_attach_snapshot(view: &TerminalView, app: &AppContext) -> AttachSnapshot.
  • Under one view.model.lock() scope: read size(), the mode (is_alt_screen_active → AltScreen; else !is_input_box_visible(&model, app) → Running; else Prompt), and copy the pieces needed for export: (a) history: iterate the last blocks of the block list newest-first until HISTORY_SNAPSHOT_MAX_BYTES is reached, for each completed command block collect a synthesized prompt line \r\n\x1b[2m❯ {command}\x1b[0m\r\n plus rows_to_ansi_text over its output grid (respecting displayed_output_rows the way the renderer does, so trimmed agent output is trimmed here too); (b) live region: AltScreen → export the alt grid's screen; Running → export the active block's output grid: rows above the visible window through rows_to_ansi_text (counted against the history budget), then the visible window through grid_screen_to_ansi; Prompt → nothing (the cursor ends up on a fresh line at the bottom). Build the byte vector after dropping the lock: SGR 0, CSI ?1049l (main screen), history bytes, then \r\n × rows (pushes history into scrollback so the screen dump can use absolute positions), CSI H, then for AltScreen CSI ?1049h + screen dump, else the screen dump, then modes_to_ansi.
  • Cursor for Running: cursor_render_point of the active output grid translated into the visible window; for Prompt: row rows-1, col 0.
  • Cost: cap the total under 512 KiB; the history walk stops at the budget. Measure: a 10 MB-output block must snapshot in under 20 ms (only the last rows are visited — never stringify the whole block).

Task 3 — Byte fan-out changes in the terminal layer

  • Expose the inactive receiver: in app/src/terminal/view.rs keep a clone of inactive_pty_reads_rx on TerminalView (it is already handed to PtyRecorder at :2564) with pub(crate) fn pty_reads_receiver(&self) -> Option<async_broadcast::InactiveReceiver<Arc<Vec<u8>>>> (None for terminals without a byte stream, e.g. read-only restored panes or mock managers).
  • Turn on overflow on the broadcast sender at both creation sites (terminal_manager.rs:122, 294): pty_reads_tx.set_overflow(true), so a slow consumer never causes send_pty_read_event to drop new bytes for everyone; slow receivers instead observe RecvError::Overflowed(n). Update record_pty_bytes (recorder.rs:210) to treat Overflowed as "continue" (log once) and Closed as exit. Add a test in recorder_tests.rs (or the manager's tests) that a lagging receiver sees Overflowed and the fast one sees every chunk.

Task 4 — Attachments and relay (app/src/remote_control/terminal_streams.rs)

  • Bridge side (main thread): attach(client_id, terminal_id, ctx) -> Result<AttachInfo { attach_id, snapshot, receiver: InactiveReceiver }, CommandError>: resolve the view, enforce MAX_ATTACHMENTS_PER_CLIENT, build the snapshot, grab the receiver, record Attachment { client_id, terminal_id, attach_id } in the bridge (so mode/size changes and terminal closure can be routed), and observe/subscribe the terminal if not yet watched. detach(attach_id) removes the record. When a watched terminal's Event::Resize or ModelEvent::TerminalModeSwapped/AfterBlockStarted/BlockCompleted fires, or the view is dropped, the bridge sends to the owning client's channel an event terminal.resync {attach_id, snapshot, cols, rows, mode} (rebuilt) or terminal.closed.
  • Socket side (tokio): on a successful attach result, spawn a relay task per attachment: receiver.activate() → loop recv().await: Ok(chunk) → append to a coalescing buffer flushed when it exceeds OUTPUT_COALESCE_BYTES or after OUTPUT_COALESCE_MS of quiet (use tokio::time::timeout), each flush becomes one binary frame [attach_id LE u32][bytes] pushed into the connection's outbound mpsc (capacity OUTPUT_QUEUE_FRAMES); if the push would block (try_send full), drop the buffered bytes, set a "needs resync" flag and, once the queue drains below half, ask the bridge for a fresh snapshot (resync command path) — never await on a full queue inside the relay. Err(Overflowed(_)) → same resync path. Err(Closed) → send terminal.closed and stop. Detach or socket close aborts the task (keep the JoinHandles in the connection struct and abort them on exit).
  • Binary frame writer: a single writer task per socket serializes JSON and binary frames from the outbound channel in order, so a resync event always follows the last stale bytes.

Task 5 — Protocol wiring

  • Commands terminal.attach/terminal.detach and events terminal.resync/terminal.closed per protocol.html. hello.capabilities now includes them. TerminalSummary.mode/cols/rows in the state snapshot already exist (Phase 2); make sure the bridge's watchers mark dirty on terminal resize and mode events so the header badge updates even without an attachment.

Task 6 — Web viewer (terminal.js, ui/terminal_view.js)

  • On entering #/t/<id>: create the xterm instance in the pre-built container (see the Phase 3 gotcha), terminal.attach, on result term.resize(cols, rows) (once), term.reset(), term.write(snapshotBytes), register the binary handler, refit. On leaving: terminal.detach, dispose. On terminal.resync: same as the initial apply. On terminal.closed: overlay with a back button.
  • Fit rule from web-ui.html (font size search in [8, 20] px; horizontal scroll fallback); ResizeObserver + visualViewport; recompute on state when cols/rows change (the server also resyncs). Vertical: the xterm viewport gets the full available height; when rows × cellHeight exceeds it, the container scrolls.
  • Header: title, agent name and status dot, mode badge, "Show on desktop". Mode chrome placeholders for Phase 5 (composer/toolbar hidden, layout reserved).
  • Batch binary frames per animation frame (requestAnimationFrame flush) and drop to the latest resync if more than 2 MB is queued client-side.
  • Client prefs: font scale override (−/0/+) persisted in localStorage, applied as a multiplier on the fitted size but never violating the "cols fit or scroll" rule.

Out of scope

  • Input of any kind (Phase 5). Remote-driven resize (D9). Block-level rendering, selection/copy affordances beyond xterm's native selection, search, image protocols (kitty/sixel/iTerm images are not relayed — xterm ignores them), OSC 8 hyperlinks (the web-links addon handles plain URLs only).
  • Mirroring code panes, notebooks, settings panes (the web UI shows their titles only).

Verification

  • ./script/presubmit green; serializer round-trip tests pass; overflow test passes; snapshot cost test passes.
  • Desktop: run ls --color, top, vim (alt screen), htop, a Claude Code session, yes | head -c 50M, cat of a 5 MB log; on the phone each attaches with the right content and keeps up; after yes a resync restores an exact screen; vim's status line, colors and cursor position match; Claude Code's redraws (inline TUI, no alt screen) render without smearing; quitting vim returns the viewer to the main screen (the ?1049l in the stream does it).
  • Resize the desktop pane: the phone refits within a second, content re-synced. Split the pane: both terminals attachable; close the pane: terminal.closed overlay.
  • Attach from two browsers simultaneously; detach one; the other is unaffected. Attach 5 terminals from one client → the 5th is refused with too_many_attachments.
  • Desktop impact: with a client attached to a terminal printing at full speed, the desktop stays responsive and the PTY event loop's throughput is unchanged (compare time yes | head -c 200M > /dev/null in a Spirit terminal with and without an attachment; the difference must be within noise). PtyRecorder behavior unchanged when enabled.
  • Idle: an attached but quiet terminal produces no frames; CPU at baseline.

Gotchas

  • The relay task must never block the broadcast. async_broadcast receivers that fall behind now overflow (Task 3); but a receiver that is awaited slowly still holds ring-buffer slots. Keep the relay loop trivial: receive, append, try_send, never await the socket.
  • Enabling overflow changes semantics for every receiver, including the throughput recorder behind FeatureFlag::RecordPtyThroughput (crates/warp_terminal/src/local_tty/recorder.rs:17); make both existing consumers tolerate Overflowed before flipping the flag.
  • The snapshot and the live stream must join seamlessly. Bytes emitted by the PTY after the snapshot was taken but before the receiver was activated are lost. Activate the receiver before building the snapshot (both inside the same main-thread attach call), buffer anything received during the build, and let the relay start with that buffer. Since the model processes the same bytes before the snapshot reads the grid, a byte that arrived before the snapshot is reflected in the grid and will also be replayed — this is harmless for printable output but can duplicate a cursor movement. Accept the tiny window; the 1 Hz reconcile plus the next mode/resize resync bound the damage. Document this in a test-visible constant, not a comment.
  • Warp's shell bootstrap traffic is in the raw stream. OSC/DCS sequences the model consumes (prompt markers, block boundaries) reach xterm.js too; xterm ignores unknown OSC/DCS. The visible artefact is that the shell prompt in prompt mode is whatever the bootstrap PS1 renders — possibly nothing. Phase 5's composer is the user's prompt on the phone; do not try to synthesize prompt lines from the stream.
  • displayed_output_rows filters (trimmed agent output, block filters) change which rows the desktop shows; export the same rows for history so the phone and desktop agree, but export the full visible window for the live screen — the running program's cursor math assumes the full grid.
  • Wide characters and combining marks: skip spacer cells; emit the full grapheme from content_for_display; xterm's width tables can disagree with Warp's on rare code points — the roundtrip test corpus must include CJK and emoji, and a mismatch is a bug in the exporter's spacer handling until proven otherwise.
  • Do not send CSI 2J/3J in the snapshot; term.reset() on the client already clears everything, and a clear inside the stream would wipe the history we just pushed into scrollback.
  • Locks: the snapshot builder holds the model lock while reading rows — potentially thousands. Bound the rows visited by the byte budget, copy into a local Vec, drop the lock, then serialize. Never call is_input_box_visible after the lock is dropped with a stale reference; compute the mode inside.
  • Mobile Safari memory: 5000 lines of scrollback × 120 cols is fine; do not raise it. Dispose the terminal on navigation.
