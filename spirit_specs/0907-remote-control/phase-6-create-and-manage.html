Phase 6 — Create & manage

Creating and managing work from the web: new terminal in a Worktree, launch an agent (with approval mode) in a Worktree, create a Worktree (optionally with an agent), rename and delete Worktrees with the desktop's dirty-check pipeline, close tabs. This phase also refactors the modal-bound creation and deletion pipelines into headless functions and adds deferred command results.

Goal

From a phone: tap "+" on a Worktree section → New Terminal (opens on the desktop and in the web UI), or Launch agent → pick Claude Code, YOLO → a new tab starts the agent in that Worktree; "New Worktree" → name (or auto-generated) + optional agent → the worktree is created, its tab opens, the agent starts; delete a Worktree → dirty check → confirm (force if dirty) → tabs closed, folder and branch removed; close a tab with confirmation. Everything reflects on the desktop as if done there.

Prerequisites

Phases 1–5. Read app/src/workspace/view/worktrees.rs end to end and spirit_specs/0828-ade-workspaces/phase-4-worktrees.html (creation/deletion ordering rules).

Tasks

Task 1 — Deferred results in the bridge

  • execute may return CommandOutcome::Deferred; the bridge stores (client_id, command id) in a PendingCommand and completion callbacks call bridge.reply(pending, Result<Value, CommandError>) which pushes a result onto that client's channel (dropping silently if the client disconnected). Pending commands time out server-side at 5 minutes (a ctx.spawn sleep) with bridge_unavailable, so no id leaks.

Task 2 — Headless worktree creation (refactor)

  • In worktrees.rs split start_worktree_creation into: 
    pub(crate) struct WorktreeCreationOutcome { pub worktree_id: WorktreeId, pub tab_id: EntityId, pub branch: String, pub path: PathBuf, pub include_report: IncludeCopyReport }
pub(crate) fn create_worktree(
    &mut self,
    name: Option<String>,
    agent_launch: Option<AgentLaunchRequest>,
    on_done: impl FnOnce(&mut Workspace, Result<WorktreeCreationOutcome, String>, &mut ViewContext<Workspace>) + 'static,
    ctx: &mut ViewContext<Self>,
)
    name: None → generate_worktree_branch_name(&local_branches) (the composer's default). The modal's Submit handler becomes a thin caller whose on_done closes the modal on success and calls set_error on failure; the existing toasts and finish_worktree_creation stay inside create_worktree. Existing tests in worktrees_tests.rs must keep passing unchanged; add one for the None name path.
  • worktree.create {project_id, name?, agent?}: resolve the project; if not ProjectKind::Git or no primary branch → not_git_project; ensure a screen exists (project.open logic) and use its Workspace; call create_worktree; Deferred until on_done replies with {worktree_id, tab_id, branch, path} or git_failed {details}.

Task 3 — Headless worktree deletion and rename (refactor)

  • Make execute_worktree_deletion take an on_done: impl FnOnce(&mut Workspace, Result<BranchDeleteOutcome, String>, ctx) and become pub(crate) fn delete_worktree(&mut self, worktree_id, force, on_done, ctx); the dialog's Confirm subscription passes a no-op on_done (the toasts already live inside). Primary refusal and the "close tabs first, then git" ordering are unchanged.
  • worktree.dirty_check {worktree_id}: deferred; git_ops::status_is_dirty(dir, path_env) on the background executor via ctx.spawn; reply {dirty}.
  • worktree.delete {worktree_id, confirm, force}: confirm != true → invalid_request; Primary → invalid_request; run status_is_dirty first and refuse with conflict when dirty and !force (the web UI always does the check → confirm → delete sequence, but the server enforces it); then delete_worktree; reply {branch_kept}.
  • worktree.rename {worktree_id, name}: reuse the inline editor's validation (sanitize_worktree_name, non-empty, unique within the project via worktree_names_for_project) then rename_worktree; Primary → invalid_request. Extract the validation from finish_worktree_rename into a shared helper.

Task 4 — Terminal, agent and tab commands

  • terminal.create {screen_id, worktree_id?}: snapshot tab ids, dispatch NewTerminalInWorktree (when the worktree belongs to that screen's project) or AddTerminalTab { hide_homepage: true }, then diff to find the new tab and its terminal (visible_terminal_views); reply {tab_id, terminal_id}.
  • agent.launch {screen_id, worktree_id?, catalog_index, approval_mode}: validate the index against agent_catalog(); with a worktree → add_tab_in_worktree(worktree_id, Some(request)); without → create a terminal tab as above then launch_agent_in_active_tab(request); reply like terminal.create. The agent's installed flag is advisory; launching an uninstalled agent yields the shell's "command not found" in the terminal, exactly like the desktop.
  • tab.close {tab_id, confirm}: confirm != true → invalid_request; close_tabs([index], true, true, ctx); false → conflict.
  • All of these activate the owning screen first (Phase 3 helper) so the desktop shows the change; all end with mark_dirty.
  • Tests: terminal.create on Home adds a tab; agent.launch with an out-of-range index → invalid_request; worktree.delete without confirm → invalid_request; on a Primary → invalid_request.

Verification

  • ./script/presubmit green; all existing worktrees_tests.rs, host_tests.rs, view_tests.rs unchanged and green after the refactors; the New Worktree composer and Delete dialog on the desktop behave exactly as before (manual check: create, error path with an invalid name, delete clean, delete dirty with force).

  • Kill the phone's connection mid-creation → the desktop completes the creation anyway; on reconnect the new worktree is in the snapshot.

Gotchas

  • The creation pipeline must stay a single code path. The refactor moves logic, it does not copy it; the modal is a caller. Review the diff for duplicated git calls.
  • Deletion ordering is the whole game (0828 spec rule 9): tabs closed and PTYs torn down before git worktree remove. The refactor must not reorder anything; on_done fires only after the registry removal.
  • Do not hold locks across the async git calls; the pipeline already snapshots then spawns — keep it so.
  • ProjectHost::open_project is idempotent but may raise another window when that window owns the project (D11); the command resolves the owning window first to avoid surprising window focus changes.
  • Agent catalog indices are the wire ids (catalog.rs:44-196); never reorder the catalog without a protocol bump, and validate the index server-side.
  • close_tabs with skip_confirmation = true still returns false for unsaved code files; surface as conflict with a message telling the user to close it on the desktop.
