Phase 7 — Agent sessions UX

Making the phone the place you answer agents: a Sessions screen with live sessions and on-disk history (resume in one tap), needs-input alerts while the page is open, an agent context strip above the composer, quick keys for permission prompts, and explicit session status events.

Goal

When Claude Code in Worktree api-auth asks for permission, a phone with the web UI open shows a banner "Claude Code needs your input · api-auth" within a second, the tab title gets a badge, the phone vibrates; tapping the banner opens that terminal with the tool request summarized above the composer and a quick-keys row ("1", "2", "3", "y", "n", Enter, Esc). The Sessions screen lists live sessions first (needs-input at the top) and past sessions from disk with Resume.

Prerequisites

Phases 1–6. Requires FeatureFlag::AgentSessionHistory for the history half (on by default in this fork).

  • Desktop notification pipeline (for parity of wording): format_agent_notification app/src/workspace/agent_notification.rs:22 ("Task “…” is done | needs your input | failed"), inbox recording app/src/workspace/view.rs:3959, AgentInboxModel (singleton, app/src/lib.rs:1201).

  • Reveal on desktop: Phase 3's desktop.reveal.

Tasks

Task 1 — Session status events (Rust)

  • The bridge already subscribes to CLIAgentSessionsModel for dirtiness; additionally translate StatusChanged, Started and Ended into event session.status {terminal_id, tab_id, screen_id, project_id, worktree_id, agent, display_name, status, status_message, title, workspace_name} broadcast to all clients immediately (bypassing the 50 ms coalescer) so alerts are prompt and independent of snapshot diffing. Location resolution reuses the projection's index (cache the last terminal → location map on the bridge).
  • The desktop's notification settings are not consulted: the phone is a surface the user opened deliberately, so the server always sends the events and the client's own preferences decide how loudly to alert.

Task 2 — History commands (Rust)

  • history.list {project_id?, worktree_id?, agents?, limit?}: from AgentSessionHistoryModel::sessions(), filtered by scope_paths semantics (project root + its worktree dirs when project_id is given; a single worktree dir when worktree_id is given; unscoped for Home), by agent set, sorted by modified_at desc, capped (default 50, max 200); map to HistorySession { id, agent, display_name, title, cwd, branch, model, message_count, total_tokens, created_ts, updated_ts, modified_ts, first_user_prompt, last_user_prompt, preview: [{role, text, ts}], preview_truncated, resume_command, live_terminal_id: Option } where live_terminal_id comes from matching live sessions by agent + session_id as the desktop does. Also return state (ScanState serialized) and issues count. If the history flag is off → unsupported.
  • history.refresh → refresh(true, ctx); the model's Updated event marks the bridge dirty and additionally emits event history.updated so the Sessions screen refetches.
  • history.resume {history_id, screen_id?}: find the AgentSession; choose the screen (given, else the screen whose project contains cwd, else Home); workspace.resume_agent_session(session, ctx); reply with the new tab/terminal (diff pattern). history.delete {history_id, confirm} → move_session_to_trash (optional; include if cheap).

Task 3 — Sessions screen (web)

  • Live group from the snapshot (unchanged from Phase 3) with richer rows: status pill with the desktop's wording (working / needs input / failed / idle / done / cancelled), agent artwork, title, workspace · worktree, tool line (tool_name: tool_input_preview) when blocked, relative "since" using the client's first-seen time (the server has no timestamps).
  • History group: fetched with history.list on screen entry and on history.updated; filter chips (Workspace: current/all; Agent: multi-select; "Hide empty"); rows expand to show the preview messages (You/Agent/Tool with role glyphs); actions: Resume (→ history.resume then navigate to the terminal), Copy command (clipboard when available, else a copy sheet), Jump (when live_terminal_id), Delete (confirm). A "Refresh" button and the scan state line ("Scanned 312 sessions · 2 unreadable").

Task 4 — Alerts (web)

  • On session.status with status == blocked (or failed): push an alert into ui.alerts (deduped by terminal_id), render the top banner ("<agent> needs your input · <workspace> / <worktree>" with Open and Dismiss), set document.title to (N) Spirit, navigator.vibrate([30, 40, 30]) if prefs allow, play a short beep (Web Audio, generated, no asset) if prefs allow and the page has had a user gesture. The bottom-nav Sessions badge shows the count. Clearing: when the status leaves blocked, when the user opens the terminal, or on Dismiss.
  • When the alerted terminal is already the one on screen, skip the banner but flash the status pill.
  • Prefs (client settings sheet): vibrate, sound, "alert for failed too". Stored in localStorage.

Task 5 — Agent context strip and quick keys (web)

  • Above the composer on a terminal with a live agent session: a strip with the status pill, summary (or "Waiting for your answer"), and the tool request (tool_name + tool_input_preview in monospace, truncated with expand). It updates from the snapshot.
  • When status == blocked: a quick-keys row above the key toolbar: 1 2 3, y n, Enter, Esc, ↑ ↓ — each sends the byte(s) then focuses xterm. These are generic (different agents number their options differently) — no agent-specific logic.
  • Tab title in the header shows the agent's display name and brand-colored dot.

Task 6 — Desktop parity check

  • Verify that answering from the phone updates the desktop's status dot, inbox and tray entries exactly as answering at the desk does (all of them are driven by the same CLIAgentSessionsModel events; no extra work expected — this task is verification plus fixing anything that assumed the answer came from the focused view, e.g. is_navigated_away logic in app/src/terminal/view.rs:7073 should be unaffected).

Out of scope

  • Web Push / background notifications (D17). Parsing agent transcripts live (the history model's preview is enough). Killing agents (no such action on the desktop either — Ctrl-C via terminal.signal is the way). Syncing the desktop's draft text.

Verification

  • ./script/presubmit green; unit tests: history.list scope filtering against a fake model; session.status event emitted on StatusChanged.
  • Phone in the Workspaces screen; on the desktop start Claude Code in a worktree and ask it to run a command needing permission → banner within ~1 s, badge, vibration; tap Open → terminal with the context strip showing the tool request; tap "1" → the agent proceeds, banner clears, status pill shows working; when it finishes, the pill shows done.
  • Sessions → History lists yesterday's sessions for the current Workspace; Resume opens a new tab on the desktop and phone in the right cwd running the resume command; Copy command works; filters work; Refresh rescans.
  • Failed session (kill the agent's network) → "failed" pill, optional alert.
  • Two phones: both get the alert; answering on one clears it on both after the status change.

Gotchas

  • No timestamps on live sessions (CLIAgentSession has none); "since" is client-side only and resets on reload. Do not add fields to CLIAgentSession for this.
  • session.status bypasses the coalescer but must still be delivered in order relative to state; send both through the same broadcast so the writer task preserves ordering.
  • History scanning is disk-heavy (scan_home walks agent home dirs); never trigger refresh(true) automatically from the web — only on explicit Refresh or screen entry with the model's own TTL respected (CACHE_TTL = 60 s).
  • Audio autoplay: browsers block sound before a user gesture; create the AudioContext lazily on the first tap and keep the beep optional.
  • Vibration API is Android-only in practice; feature-detect and never depend on it.
