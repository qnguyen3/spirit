Phase 10 — Verification

Prove the whole feature: device and browser matrix, flag-off byte-identity, restart matrix, throughput and idle-CPU budgets, reconnection behavior, the full presubmit, a straggler audit, and a CLOSEOUT.md that records what was and was not verified. Manual GUI/device QA is mandatory here — earlier specs skipped it and shipped unseen UI.

Goal

A written, reproducible verification record showing Remote Control works on the supported devices, does not change the app when disabled, survives restarts and network drops, stays within performance budgets, and passes every automated check — plus a closeout listing deviations, deferrals and known issues in the format of spirit_specs/0828-ade-workspaces/CLOSEOUT.md.

Prerequisites

Phases 1–9 landed. A phone (iOS Safari), an Android device (Chrome), a tablet (iPad Safari) and a laptop with Safari, Chrome and Firefox, all on the same Wi-Fi as the desktop. Optional: Tailscale on the phone.

Tasks

Task 1 — Automated suite

  • ./script/format --check, ./script/check_no_inline_test_modules, the three clippy invocations from script/presubmit, cargo nextest run --no-fail-fast --workspace --exclude command-signatures-v2, cargo nextest run -p warp_completer --features v2, cargo test --doc, cargo deny check (new dependencies: tokio-tungstenite via axum/ws; duplicate tungstenite majors must be allowed or reconciled).
  • Targeted: cargo nextest run -p remote_control -p warp_terminal ansi_export -p warp remote_control::; count and list the tests added by this effort.
  • Cross-compile checks that work locally: cargo check -p warp --target x86_64-pc-windows-msvc (the module must compile on Windows; only LAN hostname lookup is platform-specific). Note in the closeout that Linux cross-check fails locally on freetype-sys as before and is CI-only.
  • Web: a Rust integration test (in app/src/remote_control/mod_tests.rs) fetches /, /assets/<build>/app.js and every module referenced by index.html and asserts 200 + correct content types, so a missing vendored file fails the build's tests, not a phone.

Task 2 — Flag-off byte-identity

  • Build with remote_control removed from default: no settings group registered (dump-settings-schema output identical to a pre-feature baseline except for nothing), no Settings page, no palette entries (search the palette for "Remote"), no tray entry, no pill, no listener, no remote_control log lines. Restore the feature afterwards.
  • Flag on but setting disabled (the default for new users): identical to the above except the Settings page, palette toggle and tray absence — verify no listener (lsof -nP -iTCP:7777 empty) and no idle CPU difference.

For each of: iPhone Safari (portrait + landscape), Android Chrome, iPad Safari (with and without a hardware keyboard), macOS Safari, Chrome, Firefox — run the script and tick every line; record OS/browser versions.

  1. Pair via URL (laptop) or QR (phone/tablet); reload keeps the session; Log out returns to pairing.
  2. Workspaces: open two projects, switch from the device, cards update; Home works.
  3. Workspace detail: sections match the desktop; tap tab → desktop follows; create terminal; launch agent (YOLO and Normal); new worktree with agent; rename; delete clean and dirty; close tab.
  4. Terminal: ls --color, top, vim (edit, save), htop, a 5 MB cat, yes | head -c 50M (resync recovers), Claude Code full turn including a permission answer from the device, Codex prompt via the agent composer, paste 5 KB, Ctrl-C a sleep, Ctrl-D a shell, rotate the device mid-session (fit updates), background the browser for 1 minute then return (re-attach), disable Wi-Fi 10 s (reconnect banner then recovery).
  5. Sessions: live ranking, needs-input alert (banner/badge/vibration), history list + filters, Resume, Copy.
  6. New Workspace: open folder via picker, clone with progress + cancel, create; rename/reveal/remove.
  7. Settings sheet on the device: rename device, revoke another device, log out.
  8. Accessibility spot checks: VoiceOver/TalkBack can reach the bottom nav, a tab row, the composer Send button; page zoom to 200 % on the laptop keeps layouts usable.

Task 5 — Performance budgets

  • Idle: desktop with 20 tabs, 3 agents, 2 connected phones idle → additional CPU of the Spirit process ≤ 1 % (Activity Monitor / top 60 s average); no periodic state messages when nothing changes (the 1 Hz reconcile must not produce network traffic).
  • Throughput: time yes | head -c 200M > /dev/null inside Spirit with a phone attached vs. not attached — within 10 %.
  • Snapshot cost: build_snapshot for 100 tabs ≤ 2 ms (test); attach snapshot for a 10 MB block ≤ 20 ms (test).
  • Latency: keystroke echo round trip on LAN ≤ 50 ms p95 (measure with a simple cat and a phone-side timer in a debug overlay behind a query flag).
  • Memory: Spirit RSS growth after 1 hour with a phone attached to a chatty terminal ≤ 20 MB; the browser tab ≤ 150 MB.

Task 6 — Straggler audit

  • git diff main...HEAD added lines: no //, /*, # (non-attribute), * comment lines in Rust, JS or CSS (allowed: #[…] attributes, #!/bin/bash, the module doc-comment on remote_control/mod.rs if the repo owner accepted that exception, CSS #id selectors).
  • rg innerHTML app/assets/web empty; rg 'dispatch_global_action\("remote' app/src empty except tray entries; rg 'views_of_type::<Workspace>' app/src/remote_control empty; rg -n 'unwrap\(\)' app/src/remote_control crates/remote_control reviewed (network code must not unwrap on client input).
  • No new global actions; WorkspaceAction/page-action matches exhaustive; no #[allow(dead_code)]; cargo udeps-style check that qrcode is now used.
  • Log audit: pair, rotate, connect from a phone, then rg <token prefix> ~/Library/Logs/<logfile> finds nothing.

Task 7 — CLOSEOUT.md

Write spirit_specs/0907-remote-control/CLOSEOUT.md (and copy it to the canonical spec location) with: commits per phase; what shipped (files, crates, settings, protocol version); verification results with exact commands and counts; the device matrix table with versions; the lifecycle matrix results; performance numbers; deviations from this spec with reasons; deliberate deferrals (TLS, remote resize arbiter, pane splits, Web Push, mDNS, tab rename, mouse reporting, draft sync, interface enumeration); known issues; and the manual-QA statement — "performed on <devices> on <date>" or, if anything was skipped, exactly what.

Verification

  • Every task above has a written result. Any red item blocks the closeout — fix it or record it as a known issue with a repro.

Gotchas

  • Do not verify on the same machine's browser only. Loopback hides every Host/Origin/LAN bug; at least one phone over LAN is required.
  • Safari's aggressive tab suspension can make reconnection look broken; test with the screen on and note the behavior when backgrounded separately (D17 territory).
  • Baseline first: capture idle CPU and throughput numbers with the feature disabled before measuring with it enabled, on the same build.
  • Keep the spec honest: if a phase deviated, update the phase page's decision or add it to the closeout — the next feature (TLS, resize arbiter) will build on these documents.
