Phase 2 — State model & WebSocket

The protocol types, a main-thread projection of the whole app into one JSON snapshot, coalesced change detection, the /api/v1/ws push channel with a command/result envelope, and GET /api/v1/state. Verified with websocat/curl — no web UI yet.

Goal

A paired client connecting to the WebSocket receives hello then a state snapshot describing every window, screen (Workspace view), Worktree section, tab, pane and terminal, every Project and Worktree in the registry, every live CLI agent session and the agent catalog; any change on the desktop (switch tab, open a project, an agent finishing) produces a new state within ~100 ms; app.ping round-trips through the main thread.

Prerequisites

Phase 1. Read protocol.html in full — it is the contract this phase implements.

Tasks

Task 1 — Protocol types (crates/remote_control/src/protocol.rs)

  • Define ServerMessage, ClientMessage, CommandName, CommandError, ErrorCode, AppSnapshot and every nested type from protocol.html, with Clone, Debug, PartialEq, Serialize, Deserialize. Enums TerminalMode { Prompt, Running, AltScreen }, AgentSummary { None, Working, NeedsAttention }, AgentStatus, TabKind { Terminal, Code, File, AgentPicker, Settings, Mixed, Other }, PaneKind, ProjectKindWire { Git, Folder }, WorktreeKindWire { Primary, Linked }. Commands introduced by later phases are declared now (the enum is the capability list) but marked unimplemented in the bridge until their phase.
  • CommandName::as_str() and all() (via enum_iterator::Sequence if the crate is available in the workspace — it is used by warp_features — else a hand-written array with a test asserting it matches serde names).
  • Tests protocol_tests.rs: JSON golden strings for hello, a small state, a command, a result error; round-trip every enum; unknown extra fields ignored; ErrorCode→HTTP status mapping table.

Task 2 — Projection (app/src/remote_control/projection.rs)

  • pub(crate) fn build_snapshot(instance_id: &str, connected_clients: usize, app: &AppContext) -> AppSnapshot. Pure read; no locks held across calls into other entities; total cost must stay under ~2 ms for 100 tabs (measure with instant::Instant in a test).
  • Windows: app.window_ids() filtered to windows present in WorkspaceRegistry; active window = app.windows().active_window(). Screens per window from WorkspaceRegistry::screen_ids_for_window in registry order; name = workspace_switcher_label; project_id = Workspace::project_id().
  • Sections: for a project screen, reuse the same decision as the vertical tabs panel — registered worktrees in registry order (worktrees_for_project), each with the tabs whose resolved worktree id matches, then a trailing unbound section (worktree_id: None, title "Tabs") for the rest; for Home a single unbound section. Extract the existing grouping into a shared helper if vertical_tabs.rs:2093-2130 is not already callable from outside the renderer — do not fork the logic.
  • Tabs: id = tab.pane_group.id() formatted like Local Control; title = PaneGroup::custom_title else the focused pane's title; kind from pane kinds (single kind → that, several → Mixed); pinned, group_title from tab_groups[group_id]; agent_summary = summarize_tab; panes from visible_pane_ids with PaneKind via the downcast helpers used by metadata::pane_list.
  • Terminal summary: lock the model once — copy is_alt_screen_active, is_read_only, terminal_title, size().rows/columns — drop the lock, then is_input_box_visible(&model_copy…). Since is_input_box_visible takes &TerminalModel, call it inside the same short lock scope before copying out, and nothing else. cwd = pwd(). Agent summary from CLIAgentSessionsModel::session(terminal_view_id).
  • Projects: projects_mru() → ProjectSnapshot with open_in_window_id/screen_id from the registry, counts from project_counts, worktrees from worktrees_for_project with open_tab_count computed from the tabs pass.
  • Sessions: every CLIAgentSessionsModel::sessions() entry located via a single pass over the tabs (build a HashMap<terminal EntityId, (window, screen, tab, worktree)> while walking; do not call resolve_session per session — it is O(tabs) each). Rank with status_item::status_rank semantics (make that function pub(crate) and reuse it).
  • Agents: agent_catalog() entries with installed = is_installed(def, path_env) where path_env is cached in the bridge (resolved once via interactive_path_env at bridge creation and refreshed every 5 minutes) — the GUI's own PATH gives false negatives.
  • Tests projection_tests.rs using the test app harness that app/src/workspace/view_tests.rs and app/src/projects/host_tests.rs use: a Home screen with two terminal tabs → two tabs in one unbound section; a project screen with a linked worktree → two sections in registry order; an agent session marks its tab needs_attention and appears first in sessions.

Task 3 — Bridge and change detection (bridge.rs, watch.rs)

  • RemoteControlBridge gains: clients: HashMap<ClientId, ClientHandle { tx: mpsc::Sender<ServerMessage> }>, latest: Option<(u64, AppSnapshot)>, dirty: bool, rebuild_scheduled: bool, state_tx: tokio::sync::broadcast::Sender<Arc<ServerMessage>> (created by the server at start and handed over in attach_server; capacity 64), watched_workspaces: HashSet<EntityId>, watched_terminals: HashSet<EntityId>.
  • mark_dirty(ctx): sets dirty; if no rebuild is scheduled, schedule one after STATE_COALESCE_MS via ctx.spawn(sleep, |bridge, (), ctx| bridge.rebuild(ctx)). rebuild: build snapshot, compare to latest (ignoring version), on change bump version, store, state_tx.send(Arc::new(ServerMessage::State{…})). When zero clients are connected, skip rebuilding entirely (stay dirty) — the first connect forces a rebuild.
  • watch.rs — fn install_watchers(bridge: &mut RemoteControlBridge, ctx): subscribe_to_model on ProjectRegistryModel and CLIAgentSessionsModel; observe on WorkspaceRegistry — and make WorkspaceRegistry's mutators call ctx.notify() (they run inside update closures; audit the call sites in app/src/projects/host.rs and app/src/workspace/view.rs); on each notification, ensure_workspace_watchers walks all_workspaces and for each unseen Workspace: observe the view (fires on every notify), subscribe_to_view for WorkspaceEvent, and for every tab's pane group subscribe_to_model(focus_state_handle); for each unseen TerminalView: observe the view and subscribe_to_model(model_events_handle) if exposed (title/exit/block events — app/src/terminal/model_events.rs:364). Weak handles only; prune dropped ids on rebuild.
  • Reconcile timer: while clients is non-empty, a 1 s ctx.spawn loop calls mark_dirty (safety net for anything unobserved, e.g. a terminal's cwd change). Stop it when the last client leaves.
  • connect(client_id, tx, ctx) -> (hello fields, Option<latest state>), disconnect(client_id, ctx), both also notify the server's connected_clients.
  • execute(client_id, command: Command, ctx) -> CommandOutcome where CommandOutcome::Immediate(Result<Value, CommandError>) | Deferred; Phase 2 implements AppPing and returns unsupported-style CommandError for every other variant through an exhaustive match (later phases replace arms).

Task 4 — WebSocket endpoint (ws.rs)

  • Route GET /api/v1/ws: Authed + Origin check (AllowedHosts::origin_matches; missing → 403) + client cap (MAX_CLIENTS, tracked with an Arc<AtomicUsize> in AppState) → WebSocketUpgrade::on_upgrade(handle_socket).
  • handle_socket: allocate client_id; create mpsc::channel::<ServerMessage>(64) for per-client replies; bridge_spawner.spawn(connect) → send hello then state; subscribe to state_tx; select! loop over (a) incoming frames — text → ClientMessage (size-capped; parse failure → result with invalid_request if an id can be extracted else close 1003), ping → pong, command → spawn a task that awaits bridge_spawner.spawn(execute) and, if Immediate, sends result (deferred results arrive on the per-client channel from the bridge); (b) per-client channel → send; (c) broadcast state → send, with RecvError::Lagged handled by re-fetching the latest snapshot from the bridge; (d) idle timeout 60 s → close. On exit, bridge_spawner.spawn(disconnect) and decrement the counter.
  • Serialization on the tokio side (serde_json::to_string of Arc<ServerMessage>); the bridge never serializes.
  • server.shutting_down: the server's stop sends it through state_tx before dropping the runtime.

Task 5 — REST state and status

  • GET /api/v1/state: bridge_spawner.spawn(|b, ctx| b.snapshot_now(ctx)) → JSON. GET /api/v1/status gains connected_clients from the atomic counter and the limits table.

Task 6 — Tests

  • mod_tests.rs: upgrade without Origin → 403; with wrong Origin → 403; with correct → 101; hello then state arrive in order; app.ping returns the instance id; a 9th client gets 503; oversized text frame closes the socket. Use tokio-tungstenite (already a transitive dependency once axum/ws is on) as the test client, in a test-only runtime like app/src/local_control/mod_tests.rs:233.
  • Bridge tests: two mark_dirty calls within 50 ms yield one broadcast; an unchanged rebuild yields none; version increases monotonically.

Out of scope

  • Any command other than app.ping (Phase 3+). Terminal streams (Phase 4). The web app (Phase 3) — the placeholder page may optionally open the socket and print raw messages for debugging, but nothing more.
  • State diffs, compression, per-client filtering.

Verification

  • ./script/presubmit green.
  • curl -H 'Authorization: Bearer <token>' 127.0.0.1:7777/api/v1/state | jq shows windows/screens/sections/tabs/panes/terminals matching the desktop; open a second Workspace, switch tabs, split a pane, launch an agent — each reflected on re-fetch.
  • websocat -H 'Origin: http://127.0.0.1:7777' -H 'Cookie: spirit_rc=…' ws://127.0.0.1:7777/api/v1/ws: hello, state, then a new state within ~100 ms of every desktop change; {"type":"command","id":"1","name":"app.ping","params":{}} → a result; idle silence past 60 s closes the socket; disabling Remote Control sends server.shutting_down then closes.
  • Idle CPU with one connected client and an idle desktop is indistinguishable from baseline (the 1 Hz reconcile must be cheap: profile build_snapshot).
  • Restart Spirit: the reconnecting websocat gets a new instance_id.

Gotchas

  • observe on a Workspace fires on every render-relevant notify — many per second while typing. The coalescer plus the structural comparison keep the network quiet; do not "optimize" by dropping either.
  • WorkspaceRegistry is mutated through update from ProjectHost; adding ctx.notify() inside its mutators is safe, but confirm no caller holds a borrow that observe callbacks would re-enter (they are deferred by the framework's effect queue, so this is fine — verify by test).
  • Do not resolve sessions with views_of_type::<Workspace>. A window holds one Workspace per open Project; always go through WorkspaceRegistry (index Recommendation; Local Control's resolver has this latent bug — do not copy it).
  • Locks: the projection touches many TerminalModels; each lock scope must be a handful of field reads. If is_input_box_visible needs app while the lock is held, that is the existing precedent (view.rs:7618 holds it the same way); never call anything that could lock another model or emit while inside.
  • Deferred results need the per-client channel, which is why replies are not sent through the broadcast. Keep ClientHandle in the bridge only (main thread) and hand the receiving half to the socket task.
  • Broadcast lag: tokio::sync::broadcast drops the oldest messages for slow receivers and reports Lagged; since every state is a full snapshot, the recovery is simply "fetch latest", never "replay".
  • Feature check inside the bridge too: like LocalControlBridge::handle_request, execute re-checks the flag and the enabled setting so a command in flight during disable is refused.
